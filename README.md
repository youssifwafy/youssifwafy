## ◈ Featured Projects

<details>
<summary><b>⬡ DevScreen — AI-Powered Technical Recruitment Platform</b></summary>

<br/>

> Redefining how engineering teams evaluate candidates — replacing subjective resume screening with objective, AI-driven code intelligence. Built end-to-end at the **AISprint Hackathon (GDG Cairo × EUI)** and recognized by the partnering company for intern conversion pipeline integration.

<div align="center">

| Attribute | Detail |
|:---|:---|
| **Stack** | Next.js · React · TypeScript · Supabase · PostgreSQL · Google Gemini 2.5 Flash · CodeBERT · ts-morph |
| **Scale** | Full-stack SaaS platform with real-time AI evaluation pipeline |
| **Performance** | Sub-8-second end-to-end candidate evaluation from GitHub URL to scored output |
| **Security** | Supabase row-level security · JWT auth · scoped API access |
| **Impact** | Reduced mock screening time from hours to minutes; recognized by hackathon partner for intern pipeline integration |
| **Repository** | [![GitHub](https://img.shields.io/badge/View_Repository-6d28d9?style=flat-square&logo=github&logoColor=white)](https://github.com/youssifwafy) |

</div>

DevScreen ingests a candidate's GitHub profile URL and runs a multi-stage AI evaluation pipeline: **ts-morph** extracts Abstract Syntax Trees from TypeScript repositories to capture structural code patterns; **CodeBERT** generates dense semantic embeddings that encode language-agnostic programming intent; **Gemini 2.5 Flash** performs holistic reasoning across the combined signal to produce a ranked, explainable skill assessment. Results stream to a **Next.js** frontend via a real-time Supabase subscription, delivering scored output in under 8 seconds — making DevScreen the fastest path from GitHub URL to actionable hiring signal.

</details>

<details>
<summary><b>⬡ FIFA World Cup 2026 — Event Management System</b></summary>

<br/>

> Enterprise-grade stadium operations platform architected for real-time emergency response, multi-role access, and high-volume ticketing — designed and delivered as the sole backend engineer on an 8-member team.

<div align="center">

| Attribute | Detail |
|:---|:---|
| **Stack** | Node.js · Express · MSSQL · Vanilla JS · HTML · CSS · Server-Sent Events (SSE) |
| **Scale** | 12-entity relational schema · RESTful API covering ticketing, emergency, food, and event management |
| **Performance** | Real-time SSE dispatch with zero WebSocket overhead; instant fan-to-staff signal relay |
| **Security** | Role-based access control (Fan / Staff / Admin / Vendor) · JWT authentication · bcrypt password hashing |
| **Impact** | Zero integration issues pre-deployment; full API/schema documentation delivered to 8-member team |
| **Repository** | [![GitHub](https://img.shields.io/badge/View_Repository-6d28d9?style=flat-square&logo=github&logoColor=white)](https://github.com/youssifwafy) |

</div>

The system's most technically demanding feature is its **seat-location-based emergency dispatch engine**: when a fan triggers a distress signal, the system resolves their exact seat coordinates against a stadium zone mapping, routes the alert to the nearest staff dashboard via Server-Sent Events, and surfaces the incident in real time — without WebSocket handshake overhead. The 12-entity MSSQL schema was designed to support concurrent ticketing, vendor order management, and live event orchestration under stadium-scale load. As Documentation Lead, I authored the full API contract and schema diagram reference that eliminated pre-deployment integration conflicts across all 8 team members.

</details>
